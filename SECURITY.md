# Security policy

## Authorized and intended use

`minifuzz` is a **defensive, educational** tool. It fuzzes one thing: the
SVCF parser bundled in this repository, which exists to demonstrate memory
safety bugs. There is no option to aim it at another program, a host or a
network endpoint, and it performs no network I/O at all.

## The planted bugs are deliberate

`src/target_svfc.cpp` contains two intentional off-by-one bounds checks
(32-byte key buffer, 64-byte value buffer) guarded by redzones so the fuzzer
can demonstrate detection, minimisation and reproduction.

- Never copy those checks into production code.
- The format has no real-world use: do not parse untrusted data with it.
- If you reuse the fuzz loop for your own target, remove or replace
  `target_svfc.cpp` and implement `run_target` for your code.

## Reporting a vulnerability in minifuzz itself

- Crash, hang or unbounded memory on unexpected input → GitHub security
  advisory with the smallest reproducing input.
- A run that reports a crash for input that does not touch a redzone (a
  rejection being counted as a crash) is a correctness bug worth reporting.
- A `--seed` that does not reproduce across platforms is a determinism bug.

## Secrets

- No credentials, tokens or private keys are present.
- `corpus/` and `results/crashes*/` contain parser bytes generated by this
  tool: 7–79 byte binary blobs with no external meaning. They are safe to
  commit; real-world corpora from systems you assess are not, and should stay
  out of version control.
